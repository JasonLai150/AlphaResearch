What we implemented all green

🌐 Session API done

Public surface for the chat UI.

  • POST /sessions {user_id, goal} → creates session + root job, enqueues run
  • GET /sessions/{id}/full → resume: session + job tree + runs + transcript + artifacts
  • GET /sessions/{id}/stream → SSE live event bus
  • GET /sessions/{id} snapshot · /healthz

⚙️ The runner done

asyncio loops co-hosted with the API; single active leader (Redis lease).

  • session_loop → spawns main agent (Cloud Run Job)
  • dispatch_loop → spawns sub agents (Modal)
  • reconcile_loop → poll → finalize → ship artifacts → cancel orphans → cleanup

🧭 Main agent done

Research director (Claude Code CLI, Cloud Run Job).

  • Builds a validated ResearchPlan; one sub-agent per diverse idea
  • Dispatches via POST /internal/dispatch (no shared FS)
  • Polls children + reads artifacts over HTTP; synthesizes findings

🔬 Sub agents done

One isolated experimenter per idea (Claude Code CLI, Modal).

  • Reads its dispatch record from a per-session volume
  • Runs the experiment; writes result.json atomically + .done sentinel
  • Drops plots/checkpoints into the volume → runner ships to GCS

🔌 Internal API + telemetry done

Agents → runner, per-session token auth.

  • /internal/events, /transcript, /dispatch, /children[/artifacts]
  • Hooks stream every tool call + user turn into the chat
  • Routes hidden from OpenAPI

🗃️ State, artifacts, deploy done

Redis = source of truth; GCS = blobs.

  • Jobs/tree/runs/events/transcript/queues/budgets/guardrails
  • GCS upload w/ deterministic (idempotent) artifact ids
  • deploy/api.Dockerfile (builds) + idempotent deploy_cloudrun.sh + Modal app

Hardening — 13 SEV-1/SEV-2 fixes + 2 adversarial reviews

Per-session ephemeral tokens (no shared-secret blast radius) · runner leader lease (no double-spawn on deploys) · idempotent spawns · atomic results + sentinel · orphan-child cancellation · reconcile re-fetch · deterministic artifact ids · field-level status writes · startup Redis ping. Midpoint review: 14 findings confirmed & fixed. Final review: running now. Full per-fix map in docs/backend-mvp-notes.md.

Testing the whole user flow — staged plan

Stage 0 · Logic e2e, fully mocked works today

Command: uv run pytest tests/test_e2e_smoke.py
  • POST /sessions → session_loop spawns main → main POSTs /internal/dispatch → dispatch_loop spawns sub → sub writes result+artifact → reconcile finalizes → GET /full shows the tree. Confirms every seam fits.

Stage 1 · Real agents, local, no cloud ~1 day to add

Highest ROI: exercises real Claude-Code planning/dispatch/training without GCP/Modal.
  • Implement a local spawn backend: docker run the main-agent / sub-agent images on localhost, mounting a local dir as the per-session "volume", with ALPHA_INTERNAL_RUNNER_URL pointed at the host. Swap it in behind cloud_run_client.spawn_main_agent_job / modal_client.spawn_sub_agent via a config flag.
  • Run uvicorn orchestrator.api:app against real Redis Cloud; curl POST /sessions; tail the SSE stream.
  • Use a toy plan (tiny budget_steps, fast env) so a sub-agent finishes in seconds, not hours.
  • Validates: real plan generation, dispatch hooks, internal-API auth, telemetry streaming, reconcile, synthesis — the actual agent behavior.

Stage 2 · Full cloud round-trip needs 1 fix first

Deploy: scripts/deploy_cloudrun.sh + modal deploy infra/modal_app.py (+ create secrets).
  • Blocker: the runner reads sub-agent results from a local volume path, but Cloud Run can't mount a Modal Volume. Fix reload_volume() to hydrate via the Modal SDK, or have sub-agents push results to a new /internal/result endpoint. (Detailed in docs/backend-mvp-notes.md.)
  • Then: real POST /sessions → watch SSE → GET /full until the root job is terminal → inspect synthesis + gs:// artifacts.
